## Questions

1. What is the difference between `@ApiResponse` and your actual runtime behavior?
2. Why add example bodies to POST in Swagger?

---

## Answers

1. `@ApiResponse` documents possible status codes and response types in OpenAPI but it does not enforce them at runtime.

Swagger UI can be different from reality if decorators aren't updated.

2. Example bodies let Swagger Try it out pre-fill valid JSON for frontend integration.

### Reviewer comments

- **Q1:** Correct core distinction: `@ApiResponse` is metadata for OpenAPI/Swagger only; runtime comes from controller returns, thrown exceptions (`NotFoundException` → 404), `ValidationPipe` (400), and guards (401). Good call that docs can drift if decorators aren't kept in sync. **Polish:** document common error responses too (400, 404), not just success.
- **Q2:** Good: examples power **Try it out** and help frontend integrators. **Deepen:** they also reduce trial-and-error 400s and help reviewers/onboarding — usually via `@ApiProperty({ example: '...' })` on DTO fields. Docs: [NestJS operations](https://docs.nestjs.com/openapi/operations), [Types and parameters](https://docs.nestjs.com/openapi/types-and-parameters).
